# 长期适配度计算

## 交互原则

- 每轮只问一个问题，不输出后台计算
- 用户描述事件后，逐条询问方向/强度/重要性
- 结果只给概率变化和分档建议，不展示公式

## 流程

### Step 1: 设定先验概率

```
在没有任何互动之前，仅基于第一印象、外在条件、初步了解，
你直觉上觉得长期适配的概率大概是多少？
（建议不超过 50%）
```

### Step 2: 收集证据事件

每事件三问：

```
方向：这件事让你对这段关系的感觉是？
  [正面] / [中性] / [负面]

强度：这个感觉有多强？
  [大] / [中] / [小]

重要性：这件事判定关系有多关键？
  [大] / [中] / [小]
```

### Step 3: 遗漏提醒

当用户表示没有更多事件时（无论事件数多少），主动提醒回顾，
**正面和负面各举一半**，数据越多判断越准：

```
想再确认一下。数据越多判断越准，你再想想：

好的方面：
- 她有没有在某个瞬间让你感到特别被理解？
- 你们之前一起度过难关的经历？她的表现怎么样？
- 她对你的朋友/家人怎么样？

不好的方面：
- 你们最近一次不愉快是什么事？怎么收场的？
- 她有什么事让你觉得"以后可能是个大问题"？
- 你们对"关系应该是什么样的"有没有分歧？

有要补充的吗？
```

每次遗漏提醒时根据用户已输入的事件类型动态调整示例，保持好/坏各半。 ### Step 4: 结果输出

**概率极端时（<5% 或 >95%）**：不说教不分析，给一句共情的话，邀请补充更多信息。
**概率中间时**：简要说明关键推动事件和分档建议。

### Step 4: 执行计算

后台计算后验概率。向用户输出：
- 概率变化（先验 → 后验）
- 最关键的推动事件
- 分档建议

### Step 5: 追踪

记录本轮结果，有新事件随时重新带入。
