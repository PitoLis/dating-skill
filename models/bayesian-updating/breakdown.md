# 情感破裂风险评估

## 交互原则

- 每轮只问一个问题，不输出后台计算
- 事件结束前不展示概率

## 流程

### Step 1: 设定先验概率

```
不考虑具体事件，仅凭当前关系的整体感觉，
你觉得这段关系正在走向结束的概率大概是多少？
（建议保守起步，如 10%~20%）
```

### Step 2: 收集证据事件

每事件三问：

```
方向：这件事让你对这段关系的感觉是？
  [正面] / [中性] / [负面]

强度：这个感觉有多强？
  [大] / [中] / [小]

重要性：这件事判定关系有多关键？
  [大] / [中] / [小]
```

### 引导参考（Agent 内部使用）

帮用户校准判断：

| 事件 | 方向 | 强度建议 | 说明 |
|------|------|---------|------|
| 频繁冷战（每周+） | 负面 | 大 | 强负面信号 |
| 回避深度对话 | 负面 | 中~大 | 较强负面信号 |
| 减少见面/聊天频次 | 负面 | 中 | 中等负面信号 |
| 偶尔一次争吵 | 负面 | 小~中 | 弱信号，健康关系也常见 |
| 朋友说你们很好 | 正面 | 小~中 | 正向信号 |
| 对方主动解决问题 | 正面 | 中~大 | 正向信号 |

### Step 3: 遗漏提醒

当用户表示没有更多事件，且事件≤3个或概率极端时：

```
目前信息还比较有限。破裂信号容易遗漏，你回想一下：

- 吵架之后，是不了了之还是会沟通解决？
- 对方最近对你的态度有变化吗？更疏远还是跟以前一样？
- 你在关系中感觉更多的是安全还是焦虑？
- 对方有在回避跟你独处或深度聊天吗？
- 最近的亲密接触有变化吗？
- 共同朋友有没有说过什么？

有没有需要补充的？
```

### Step 4: 执行计算

后台计算，向用户输出：
- 概率变化（先验 → 后验）
- 最关键的推动事件
- 分档建议：
  - ≥60%：信号强烈，建议主动沟通或寻求关系咨询
  - 30%~60%：有风险，需要针对性改善
  - <30%：证据不足以支持破裂判断
